Zuerst hilft fast immer ein Blick in die Logs:

```bash
docker compose ps
docker compose logs --tail 100 <dienst>
```

Fehlermeldungen an die Oberfläche sind allgemein gehalten; die Details stehen im Log mit derselben Korrelations-ID.

## Fehler melden

Unten in der Navigation stellt **Fehler melden** einen Bericht für den Support zusammen: Ihre Beschreibung, die Version, die aufgerufene Seite ohne Suchparameter, Browser, Sprache und den letzten Fehler des Servers mit seiner Korrelations-ID. Auf Wunsch nehmen Sie ein Bildschirmfoto auf; der Browser fragt, welchen Tab, welches Fenster oder welchen Bildschirm. Bereiche, die niemand sehen soll, übermalen Sie vor dem Speichern mit der Maus schwarz.

Der Bericht wird **nicht gesendet**, sondern als JSON-Datei gespeichert, die Sie selbst weitergeben. Sitzung, Anmeldedaten und Eingaben in Formularen stehen nie darin. Mit der Korrelations-ID finden Betreiber den passenden Eintrag im Log.

## Installation und Start

| Problem | Ursache und Lösung |
|---|---|
| Ein Dienst startet nicht und nennt eine unsichere Einstellung | Ein Geheimnis steht direkt in der Umgebung statt als Datei, oder eine Pflichtangabe fehlt. Die Meldung nennt die Einstellung, nie den Wert. |
| `migrate` endet mit Fehler | Die Datenbank ist nicht erreichbar oder ein Secret fehlt. `../../scripts/generate-secrets.sh` erzeugt fehlende Secrets, dann `docker compose up -d postgres` und `docker compose run --rm migrate`. |
| Anmeldung liefert Fehler 500 nach einem abgebrochenen Start | Container mit fehlenden Netzwerk-Aliasen. `docker compose up -d --force-recreate` erzeugt sie neu. |
| Start verweigert wegen unverschlüsselter Verbindung | PostgreSQL oder Valkey liegen auf einem anderen Host ohne TLS. Siehe [Hochverfügbarkeit](/pro/hochverfuegbarkeit/). |
| Ports 80 oder 443 sind nicht verfügbar | Rootless Docker oder Podman dürfen keine niedrigen Ports öffnen, siehe [Installation](/guides/installation/#2-docker-rootless-installieren). |
| Zertifikat wird nicht ausgestellt | Für ACME müssen Port 80 und 443 aus dem Internet erreichbar sein und die DNS-Namen auf den Server zeigen. Im internen Netz `SA_UI_TLS=internal` setzen. |

## Anmeldung

| Problem | Ursache und Lösung |
|---|---|
| OIDC-Anmeldung wird abgelehnt | Keine Gruppe des Kontos passt zur Zuordnung, oder der Claim heißt anders als `groups`. Prüfen Sie die Zuordnung unter **Einstellungen › Anmeldung**. |
| Identity Provider nicht erreichbar | Lokale Konten melden sich weiter an. Gespeicherte OIDC-Konfiguration abschalten: `docker compose run --rm cli admin disable-oidc` |
| Lokales Konto gesperrt, Passwort oder Authenticator verloren | **Einstellungen › Benutzer › Zugang zurücksetzen** und den neuen Einrichtungslink weitergeben; ohne Oberfläche `docker compose run --rm cli admin reset-totp --username <name>` bzw. `admin unlock` |
| Sitzung endet unerwartet | Nach 30 Minuten Leerlauf oder 12 Stunden endet jede Sitzung. Ein deaktiviertes Konto verliert die Sitzung bei der nächsten Erneuerung. |

## Agents und Collector

| Problem | Ursache und Lösung |
|---|---|
| „Server nicht erreichbar“ bei der Registrierung | DNS, Routen oder Firewall zwischen Gerät und Server. Die Meldung nennt Host und Port. |
| Registrierung bricht wegen der CA ab | Der Fingerprint im Befehl passt nicht zur Root-CA, oder ein Proxy bricht TLS auf. Nehmen Sie den Agent-Host von der TLS-Inspektion aus. |
| Token abgelehnt | abgelaufen, aufgebraucht oder widerrufen. Erzeugen Sie ein neues. |
| Agent erscheint nicht als Asset | Er wartet auf Freigabe unter **Agents**. Ohne Freigabe wird er nach der Frist gesperrt. |
| Agent meldet sich nicht mehr | Zertifikat abgelaufen (Uhrzeit des Geräts prüfen) oder Agent gesperrt. Ein gesperrter Agent braucht ein neues Rollout-Token. |
| Collector findet keine MAC-Adressen | Er steht in einem anderen Netzsegment. |

## Uploads und Dokumente

| Problem | Ursache und Lösung |
|---|---|
| Datei zu groß | Grenze `SA_DOCUMENT_MAX_BYTES`, Standard 25 MiB. Ein vorgeschalteter Proxy kann eine eigene, kleinere Grenze haben; die Oberfläche nennt ihn dann als Ursache. |
| Upload abgelehnt, Scanner nicht erreichbar | Ein Virenscanner ist eingetragen, läuft aber nicht. `docker compose --profile scanner up -d`. |
| Speicher voll | Die Summe aller Versionen je Organisation ist begrenzt (`SA_DOCUMENT_QUOTA_BYTES`). |
| Katalog des BSI lässt sich nicht einlesen | Die Datei ist größer als 16 MiB, oder ein vorgeschalteter Proxy begrenzt die Größe. |

## Etiketten und Bilder

| Problem | Ursache und Lösung |
|---|---|
| Etikett zu klein, abgeschnitten oder verdreht gedruckt | Im Druckdialog den Drucker des Etiketts wählen, als Papier genau das gewählte Etikett (beim DYMO LabelWriter etwa „99012 Large Address“), Ränder „Keine“ und Skalierung 100 %. Die Ausrichtung legt die Seite selbst fest; Browser bieten dann keine Wahl zwischen Hoch- und Querformat. |
| Kein Strichcode auf dem DYMO-Etikett | Das Asset hat keine Inventarnummer, die Nummer enthält Zeichen außerhalb von ASCII (etwa Umlaute), oder sie ist zu lang für eine lesbare Breite auf diesem Etikett. Der QR-Code bleibt in jedem Fall; ein größeres Etikett nimmt längere Nummern. |
| Bild lässt sich nicht hochladen | Der Browser kann das Format nicht anzeigen, oder das Bild ist nach dem Verkleinern noch größer als 2 MB. Ein Foto als JPEG oder PNG hilft. |

## Verbindungen nach außen

Benachrichtigungen, Verzeichnisdienst, Hilfe-Assistent und Konnektoren erreichen nur Netze, die Sie freigeben. Ein Ziel im eigenen Netz braucht die passende Variable, etwa `SA_NOTIFICATION_ALLOWED_NETWORKS=public,192.168.10.5/32` ([Konfiguration](/reference/konfiguration/#netzfreigaben)). Ziele brauchen TLS 1.3 und ein gültiges Zertifikat; für eine eigene CA hinterlegen Sie deren Zertifikat in der jeweiligen Verbindung.

| Problem | Ursache und Lösung |
|---|---|
| „Adresse nicht erlaubt“ | Der Name des Ziels löst auf eine Adresse auf, die nicht freigegeben ist, oft eine private Adresse oder die eines Overlay-Netzes. Freigabe wie unter [Netzfreigaben](/reference/konfiguration/#netzfreigaben) beschrieben, in der vorhandenen Zeile der `.env`, dann `docker compose up -d`. |
| Freigabe gesetzt, wirkt aber nicht | Die Variable steht zweimal in der `.env`, die spätere (oft leere) gilt. Prüfen mit `grep -n ALLOWED_NETWORKS .env`; nur eine Zeile je Variable behalten. |
| Gotify: „Token abgelehnt (401/403)“ | Gotify lehnt den Token ab. Nötig ist das Token einer **Anwendung** (in Gotify unter „Apps“, beginnt mit „A“); ein Token unter „Clients“ kann nur lesen. Token unter **Ziel bearbeiten** neu eintragen. |
| „Pfad beim Ziel nicht gefunden (404)“ | Die Adresse erreicht den Server, aber den Pfad gibt es dort nicht. Prüfen Sie beim Webhook den Pfad hinter dem Host und bei Gotify, dass die Adresse auf Gotify selbst zeigt, ohne Pfad wie `/message`. |

## Systemzustand

Die Seite **Systemzustand** zeigt, ob Datenbank, Valkey, Job-Worker und Virenscanner antworten. Wartet ein Auftrag lange über seine Zeit hinaus, läuft der Worker vermutlich nicht: `docker compose logs worker`.
