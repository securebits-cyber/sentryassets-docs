A look at the logs helps first almost every time:

```bash
docker compose ps
docker compose logs --tail 100 <service>
```

Error messages in the web UI are generic; the details are in the log under the same correlation ID.

## Report a problem

At the foot of the navigation, **Report issue** puts together a report for support: your description, the version, the page opened without search parameters, browser, language and the server's last failure with its correlation ID. If you like, capture a screenshot; the browser asks which tab, window or screen. Black out what nobody should see with the mouse before saving.

The report is **not sent**; it is saved as a JSON file you pass on yourself. Session, sign-in data and form input are never in it. With the correlation ID, operators find the matching entry in the log.

## Installation and start

| Problem | Cause and solution |
|---|---|
| A service does not start and names an unsafe setting | A secret is given directly in the environment instead of as a file, or a required value is missing. The message names the setting, never the value. |
| `migrate` ends with an error | The database cannot be reached or a secret is missing. `../../scripts/generate-secrets.sh` creates missing secrets, then `docker compose up -d postgres` and `docker compose run --rm migrate`. |
| Sign-in fails with error 500 after an interrupted start | Containers with missing network aliases. `docker compose up -d --force-recreate` creates them again. |
| Start refused because of an unencrypted connection | PostgreSQL or Valkey are on another host without TLS. See [High availability](/en/pro/hochverfuegbarkeit/). |
| Ports 80 or 443 are not available | Rootless Docker or Podman may not open low ports, see [Installation](/en/guides/installation/#2-install-docker-rootless). |
| No certificate is issued | For ACME, ports 80 and 443 must be reachable from the internet and the DNS names must point to the server. In an internal network set `SA_UI_TLS=internal`. |

## Sign-in

| Problem | Cause and solution |
|---|---|
| OIDC sign-in is refused | No group of the account matches the mapping, or the claim is not called `groups`. Check the mapping under **Settings › Sign-in**. |
| Identity provider not reachable | Local accounts go on signing in. To switch off the stored OIDC configuration: `docker compose run --rm cli admin disable-oidc` |
| Local account locked, password or authenticator lost | **Settings › Users › Reset access** and pass on the new setup link; without the web UI `docker compose run --rm cli admin reset-totp --username <name>` or `admin unlock` |
| Session ends unexpectedly | Every session ends after 30 minutes idle or 12 hours. A deactivated account loses its session at the next renewal. |

## Agents and collector

| Problem | Cause and solution |
|---|---|
| "Server not reachable" at enrolment | DNS, routes or a firewall between device and server. The message names host and port. |
| Enrolment stops because of the CA | The fingerprint in the command does not match the root CA, or a proxy breaks TLS open. Exempt the agent host from TLS inspection. |
| Token refused | expired, used up or revoked. Create a new one. |
| Agent does not appear as an asset | It waits for approval under **Agents**. Without approval it is blocked after the period. |
| Agent stops reporting | Certificate expired (check the device's clock) or agent blocked. A blocked agent needs a new rollout token. If **Settings › Activity** shows **revoked certificate presented again**, its identity was copied: see [Certificates and renewal](/en/guides/agents/#certificates-and-renewal). |
| Collector finds no MAC addresses | It is in another network segment. |

## Uploads and documents

| Problem | Cause and solution |
|---|---|
| File too large | Limit `SA_DOCUMENT_MAX_BYTES`, 25 MiB by default. A proxy in front may have a smaller limit of its own; the web UI then names it as the cause. |
| Upload refused, scanner not reachable | A virus scanner is set but does not run. `docker compose --profile scanner up -d`. |
| Storage full | The sum of all versions per organisation is limited (`SA_DOCUMENT_QUOTA_BYTES`). |
| A BSI catalogue cannot be imported | The file is larger than 16 MiB, or a proxy in front limits the size. |

## Labels and pictures

| Problem | Cause and fix |
|---|---|
| Label printed too small, cut off or turned | In the print dialog, choose the label's printer, exactly the chosen label as paper (for the DYMO LabelWriter, for example, "99012 Large Address"), no margins and 100 % scale. The page sets the orientation itself; browsers then offer no choice between portrait and landscape. |
| No barcode on the DYMO label | The asset has no inventory number, the number holds characters outside ASCII (such as umlauts), or it is too long for a readable width on this label. The QR code remains in any case; a larger label takes longer numbers. |
| Picture cannot be uploaded | The browser cannot show the format, or the picture is still larger than 2 MB after shrinking. A photo as JPEG or PNG helps. |

## Outgoing connections

Notifications, directory service, help assistant and connectors reach only networks you allow. A target in your own network needs the matching variable, such as `SA_NOTIFICATION_ALLOWED_NETWORKS=public,192.168.10.5/32` ([Configuration](/en/reference/konfiguration/#network-allowances)). Targets need TLS 1.3 and a valid certificate; for an own CA, add its certificate to the connection.

| Problem | Cause and solution |
|---|---|
| "Address not allowed" | The target's name resolves to an address that is not allowed, often a private address or one of an overlay network. Allow it as described under [Network allowances](/en/reference/konfiguration/#network-allowances), in the existing line of `.env`, then `docker compose up -d`. |
| Allowance set but without effect | The variable appears twice in `.env`, and the later (often empty) one counts. Check with `grep -n ALLOWED_NETWORKS .env`; keep one line per variable. |
| Gotify: "token refused (401/403)" | Gotify refuses the token. It needs the token of an **application** (in Gotify under "Apps", starting with "A"); a token under "Clients" can only read. Enter the token again under **Edit target**. |
| "path not found at the target (404)" | The address reaches the server, but the path does not exist there. For a webhook check the path after the host; for Gotify check that the address points to Gotify itself, without a path such as `/message`. |

## System health

The page **System health** shows whether database, Valkey, job worker and virus scanner answer. If a job waits long past its time, the worker is probably not running: `docker compose logs worker`.
