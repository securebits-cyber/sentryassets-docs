After the [installation](/en/guides/installation/) you sign in with the first administrator account. The setup wizard leads through the basic setup; every step can also be found later under **Settings**.

## Setup wizard

The wizard opens at the first sign-in and stays available under **Settings › Setup wizard**. It leads through, in this order:

1. **Organisation:** the name of your organisation; it appears in the sidebar and on labels.
2. **Location:** the first location in the location tree (site, building, floor, room).
3. **Sign-in (optional):** check whether OIDC is reachable, if you use an identity provider (see below).
4. **First agent:** create a rollout token and copy the ready-made installation command (see [Agents](/en/guides/agents/)).

In an empty installation the wizard also offers to load **example data**: an invented company with sites, people, suppliers, devices, relations, licences and contracts. They can be removed again in one step; example entries that your own data refer to, or that you changed, stay. While example data are loaded, the overview says so.

## Sign-in: local accounts and OIDC

SentryAssets knows two equal ways to sign in:

- **Local accounts** with username, password and a one-time code from an authenticator app (TOTP). The one-time code is **mandatory**; there is no local account without it.
- **OIDC** through your identity provider, such as Entra ID, Keycloak, Authentik or Okta. OIDC is **optional**.

Both apply side by side. Without an identity provider you work with local accounts only. With OIDC you keep local accounts for people without a company account and as a way in if the identity provider fails.

## Local accounts

Only administrators create local accounts; nobody can register themselves. The person chooses the password, so nobody else knows it.

<Steps>

1. Open **Settings › Users** and choose **Create local account**. Enter the username (lowercase letters, digits and `. _ @ -`), display name, optionally the email address and the [role](/en/reference/rollen/).

2. SentryAssets shows a **setup link**, this one time only. Give it to the person over a confidential channel, such as in person or an encrypted messenger. Whoever has the link can set up the account.

3. The person opens the link, scans the QR code with their authenticator app, chooses a password and confirms with the first one-time code. They are then signed in, and the link no longer works.

</Steps>

<Aside>
A setup link is valid for 72 hours. Once it has expired, the user list shows "Link expired"; create a new one with **Reset access**.
</Aside>

- **Password rules:** at least 12 characters, without the username and without "sentryassets". A long sentence is easier to remember than a short, complicated password.
- **Change the role:** for local accounts, pick the role right in the user list; it applies at once, also in running sessions.
- **Lost password or authenticator:** **Reset access** invalidates password and one-time codes, ends all sessions of the account and creates a new setup link.
- **Change your own password:** everyone changes their password and authenticator in their **profile**.
- **Failed attempts:** after five failed sign-ins, the account is locked for a growing time.
- **Forbid new local accounts:** under **Settings › Users**, switch off **Allow creating new local accounts** if new people should only come through OIDC. Existing local accounts go on signing in and can be reset.

Creating, changing roles, resetting and the setting for new accounts ask for a fresh confirmation of your sign-in: a one-time code for local accounts, a renewed sign-in at the identity provider for OIDC accounts.

### Commands on the server

These commands need no web UI, for example when nobody can get in any more:

```bash
# Create an administrator (asks for the password, shows the TOTP address)
docker compose run --rm cli admin create-admin --username admin

# New TOTP secret for a local account; running sessions end
docker compose run --rm cli admin reset-totp --username admin

# Lift the lockout after failed attempts, enable a disabled account again
docker compose run --rm cli admin unlock --username admin
docker compose run --rm cli admin enable-account --username admin
```

<Aside>
To allow OIDC only, set `SA_LOCAL_ACCOUNTS=disabled`. There is then neither local sign-in nor setup links, and running local sessions end. Make sure first that an administrator can sign in via OIDC.
</Aside>

## Sign-in with OIDC (optional)

With OIDC, SentryAssets signs people in through your identity provider (OpenID Connect with authorization code and PKCE). Accounts are created at the first sign-in; the role follows the groups at every sign-in.

<Steps>

1. Create a confidential application (with client secret) for SentryAssets at the identity provider:
   - Redirect address: `https://<SA_UI_HOST>/api/v1/auth/oidc/callback`
   - Address after sign-out: `https://<SA_UI_HOST>/login`
   - The provider sends the groups in the `groups` claim (the name can be set with `SA_OIDC_ROLE_CLAIM`).

2. Under **Settings › Sign-in**, enter issuer, client ID, client secret and the mapping of groups to roles as a draft, for example `sa-admins=admin` and `sa-auditors=auditor`. The roles are explained in [Roles and permissions](/en/reference/rollen/).

3. Check the draft with a **trial sign-in** using an account that the mapping makes an administrator. Only a successfully tested draft can be activated.

4. **Activate** the sign-in. The sign-in page then offers both: the company account and local accounts.

</Steps>

- **No matching group:** the sign-in is refused.
- **Several groups:** the first role in the order administrator, information security, editor, data protection, auditor, read only applies (see [Roles and permissions](/en/reference/rollen/)).
- **Role:** for OIDC accounts, change the role through the groups at the identity provider, not in SentryAssets.
- **Permissions revoked:** at every session renewal SentryAssets checks that the account is still active. Revoked groups take effect at the next sign-in at the latest. With [SCIM](/en/pro/scim/) a block applies at once.
- **E-mail address:** SentryAssets takes the `email` claim only if the provider reports the address as confirmed. If it does not send `email_verified`, as Microsoft Entra ID depending on its setup, and your IT maintains the addresses there, switch on **Addresses of this provider count as confirmed** in the draft (`SA_OIDC_TRUST_EMAIL` in the server configuration). Without a confirmed address the account receives no [notifications by e-mail](/en/guides/benachrichtigungen/#which-address-applies).
- **Sessions:** idle 30 minutes, absolute lifetime 12 hours (`SA_SESSION_IDLE_MINUTES`, `SA_SESSION_ABSOLUTE_HOURS`).
- **Switching off:** OIDC can only be switched off when a local administrator account is set up. If the identity provider fails, `docker compose run --rm cli admin disable-oidc` switches the configuration stored in the web UI off.

### OIDC in the server configuration

Alternatively, set OIDC in a `docker-compose.override.yml` with `SA_OIDC_ISSUER`, `SA_OIDC_CLIENT_ID`, `SA_OIDC_ROLE_MAPPING` and `SA_OIDC_CLIENT_SECRET_FILE` (as a secret file). This configuration takes precedence; the web UI then only shows it.

## Managing users

Under **Settings › Users** you see all accounts with role, sign-in method, status and last sign-in. **Disable** revokes access at once, with "Undo" in the notice. You do not change your own account there; that is what the profile is for. One administrator and one way to sign in always remain.

**Email address:** for local accounts, choose **Change** in the **Email** column, enter the address and choose **Save**; an empty field removes it. This works for your own account too, for example the account from `cli admin create-admin`, which is created without an address. The page asks you to confirm your sign-in first. [Email notifications](/en/guides/benachrichtigungen/) go to this address, and [My devices](/en/pro/selbstbedienung/) finds the person in the directory through it; that is why only administrators set it, never the account itself. OIDC accounts take their address from the identity provider.
