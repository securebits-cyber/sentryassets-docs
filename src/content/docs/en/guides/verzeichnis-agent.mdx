If SentryAssets runs at a hosting provider, the server cannot reach your domain controller in the company network. Instead of a site-to-site VPN, install the **directory agent** on a Windows server in the company network. It reads Active Directory over LDAPS and sends the results over an outbound-only, mutually authenticated connection (mTLS, TLS 1.3) to SentryAssets, like the agent and the collector.

<Badge text="Community" variant="success" /> for the computers, <Badge text="Pro" variant="note" /> for [people from AD](/en/pro/active-directory/).

## How it differs from the direct route

| | Directly from the server | Over a directory agent |
|---|---|---|
| Network path | server → domain controller (TCP 636), in your network or over a VPN | directory agent → SentryAssets (HTTPS, outbound only) |
| Domain controllers, service account, password, CA | in the interface, password encrypted on the server | only on the directory agent's computer, never on the server |
| What is read | fixed attributes | the same fixed attributes, compiled into the program |
| What the server decides | everything | only OUs, groups (Pro) and the interval |

Even a compromised server at the hosting provider therefore knows neither the service account's password nor can it ask for other attributes such as LAPS passwords or BitLocker recovery keys: the directory agent has no way to read them.

## Where it runs

A **member server** that is always on, such as a file server, is recommended. A domain controller belongs to the highest protection level, and IT-Grundschutz asks to run only the services needed there. The directory agent still runs on a domain controller; SentryAssets then points this out.

The computer needs:

- Windows Server 2016 or later (or Linux with systemd), without additional software.
- Outbound HTTPS to your SentryAssets (agent address, port 443 or 8443).
- TCP 636 (or 3269) to the domain controllers. Only private addresses are contacted; link-local addresses (`fe80::`, `169.254.`), which Windows adds for its own name, are skipped.

## Setting it up

<Steps>

1. **Prepare the service account and CA** as for the direct route, see [Connecting Active Directory](/en/guides/active-directory/). Save the CA certificate as a file on the directory agent's computer, for example `C:\SentryAssets\ad-ca.cer`.

2. Open **Settings › Directory services**, choose the route **Over a directory agent (no VPN)** in the draft and create a rollout token under **Set up a directory agent**. This asks you to confirm your sign-in again. The token is shown once.

3. **Install:** run the command shown in an **administrator PowerShell** on the computer. It downloads the program from your SentryAssets, checks its SHA-256 sum, creates `C:\ProgramData\SentryAssets\Directory` for SYSTEM and Administrators only and enrolls the device. Paste the token at the prompt; the input stays hidden.

4. **Set up access to AD**, in the same PowerShell:

   ```powershell
   & "$env:ProgramFiles\SentryAssets\Directory\sentryassets-directory.exe" set `
     --bind-name svc-sentryassets@company.local `
     --controller dc01.company.local --controller dc02.company.local `
     --ca-file C:\SentryAssets\ad-ca.cer
   ```

   The program asks for the password without showing it; it never appears on the command line. Up to four domain controllers are possible, in failover order. Everything is stored only in `C:\ProgramData\SentryAssets\Directory`, the password additionally bound to the computer with DPAPI.

5. **Test on site** (optional):

   ```powershell
   & "$env:ProgramFiles\SentryAssets\Directory\sentryassets-directory.exe" test --base-dn "OU=Clients,DC=company,DC=local"
   ```

6. **Start the service:** `Start-Service SentryAssetsDirectory`. The directory agent then appears under **Discovery › Agents** with the label **Directory agent**. Depending on the token, approve it there.

7. **Back in Settings › Directory services:** choose the directory agent, enter the **OUs (base DNs)**, **save the draft** and **test the connection**. The directory agent runs the test at its next contact, usually within five minutes; the result appears by itself. Then **activate**.

</Steps>

<Aside type="tip" title="Linux">
On Linux the page shows a command that creates a system user `sentryassets-directory` of its own and sets up the hardened systemd service `sentryassets-directory`, as root or with `sudo`. If the service is already running, the command stops it to enrol anew and then restores the previous state, also after an error or an abort; if stopping fails, it ends before enrolling. Then set up the service account and the domain controllers with the command the page puts together from your entries, again as root or with `sudo`: it runs `set` as this system user, the program asks for the password without showing it, and the service then restarts. Without root and without `sudo` the commands stop before they change anything.
</Aside>

## In operation

- The directory agent reads at the interval set, at most once an hour. **Synchronise now** asks for a run, which it starts 15 minutes after its last start at the earliest; so it reads at most four times an hour. When the next run comes at the earliest is shown under **Settings › Directory services** as **Next run**. SentryAssets takes a run over only once it has arrived completely; an interrupted or failed run changes nothing.
- **Changing the password:** run `sentryassets-directory set` again on the computer, on Linux with the command from the setup. The interface has no field for it; the next test shows the new state.
- **Changing the route:** if you switch an existing connection from "Directly from the server (LDAPS)" to "Over a directory agent (no VPN)", SentryAssets deletes the password stored on the server when you activate it. Computers keep their links.
- **Updates:** On Windows the directory agent updates itself, only with versions the vendor signed, staggered within 24 hours. To update at once: `& "$env:ProgramFiles\SentryAssets\Directory\sentryassets-directory.exe" update; Restart-Service SentryAssetsDirectory`. On Linux it runs without write access to its program and does not update itself; use the command **Update later (Linux)** from the setup there. It checks the SHA-256 sum, replaces the program and restarts the service, without enrolling again.
- **Enrolling again on Windows:** if you run the installation command on a computer where the service is already set up, it disables the service for the time being, so that the recovery actions do not start the old program during enrollment. Afterwards the previous start type applies again, and a service that was running runs again. This also holds after an error or an abort; the previous program then stays as well. If the service stayed disabled after an interrupted run, the next run sets it to automatic and starts it.
- One directory agent serves exactly one connection. For several domains (Pro) set up one per domain.
- **Removing it:** see [Uninstalling](#uninstalling).

## Exclusions in virus scanners and EDR

Virus scanners and EDR products (such as Microsoft Defender for Endpoint, CrowdStrike Falcon, SentinelOne or ManageEngine Endpoint Central) may classify the directory agent as an unknown program, quarantine and delete it, sometimes within seconds of the download. On domain controllers and other servers the policies are often especially strict. Therefore, set up an exclusion for the program folder in your product's console **before installing**:

| System | Program folder (exclusion) | State folder |
|---|---|---|
| Windows | `C:\Program Files\SentryAssets\Directory\` with `sentryassets-directory.exe` | `C:\ProgramData\SentryAssets\Directory\` |
| Linux | `/opt/sentryassets-directory/bin/` with `sentryassets-directory` | `/var/lib/sentryassets-directory/` |

**Why the folder and not just the file:** on Windows the directory agent replaces itself in its own program folder during an update. It first stores the new version there as `.sentryassets-directory.update-…`, checks it, renames the running program to `sentryassets-directory.exe.old` and puts the new file in its place; Windows then restarts the service. The installation command also downloads the program into this folder, first as `sentryassets-directory.exe.download`. To an EDR product this looks like a service swapping an executable, and it intervenes. An exclusion by checksum (hash) applies to one version only and ends with the next update; use the folder path if your product allows it, together with the program path as a process. On Linux the directory agent does not update itself; it only needs an exclusion there if your scanner blocks the program while installing or updating it.

Notes:

- Keep the exclusion as narrow as possible: only the program folder, not `C:\Program Files\` or `/opt/` as a whole. The program folder is writable only by administrators or root.
- The state folder usually needs no exclusion. If the console reports blocked access to the certificate, the key or the stored credentials there, exclude it as well.
- Even with an exclusion the directory agent only accepts updates signed by the vendor.
- The same applies to the agent on your other devices, see [Agents](/en/guides/agents/#exclusions-in-virus-scanners-and-edr).

## Uninstalling

<Steps>

1. **Block it:** under **Discovery › Agents**, block the directory agent. Its certificate becomes invalid; it reads and reports nothing more, even while it still runs. First switch a connection that reads over it to another directory agent under **Settings › Directory services**, or deactivate it.

2. **Remove it from the computer:** under **Discovery › Agents**, in the card **Uninstall agent**, choose **Directory agent (Windows)** or **Directory agent (Linux)** and copy the command. On Windows in a PowerShell started as administrator:

   ```powershell
   Stop-Service SentryAssetsDirectory -ErrorAction SilentlyContinue; sc.exe delete SentryAssetsDirectory; Remove-Item -Recurse -Force (Join-Path $env:ProgramFiles 'SentryAssets\Directory'), (Join-Path $env:ProgramData 'SentryAssets\Directory') -ErrorAction SilentlyContinue
   ```

   On Linux in a terminal as root or with `sudo`; without either the command stops before it changes anything:

   ```bash
   (
     set -eu
     if [ "$(id -u)" -eq 0 ]; then as_root=""
     elif command -v sudo >/dev/null 2>&1; then as_root="sudo"
     else echo 'Run this as root, for example after su -' >&2; exit 1; fi
     $as_root systemctl disable --now sentryassets-directory
     $as_root rm -f /etc/systemd/system/sentryassets-directory.service
     $as_root systemctl daemon-reload
     $as_root rm -rf /opt/sentryassets-directory /var/lib/sentryassets-directory
     $as_root userdel sentryassets-directory
   )
   ```

   The command stops the service and deletes program, certificate, key and the service account's password stored there.

3. **Tidy up the AD** (optional): disable or delete the service account if nothing else needs it.

</Steps>

## Common errors

| Message | Cause and fix |
|---|---|
| The directory agent has not reported | The service is not running, not approved yet, or has no outbound connection. Check `Get-Service SentryAssetsDirectory` and make the agent address reachable. |
| The service does not start | `set` has not been run yet; without access to AD the service does not start on purpose. |
| The service does not start, "access denied" | A virus scanner or EDR product has blocked or deleted the program, see [below](#service-does-not-start-access-denied). |
| Address not allowed | The domain controller's name resolves (also) to a public or loopback address, or to link-local addresses only. The directory agent contacts private addresses only. Check on the agent's computer with `Resolve-DnsName <name>`. |
| Certificate invalid | The domain controller's name is not in its certificate, or `--ca-file` names the wrong CA. |
| Sign-in refused | Wrong bind name or password; set them again with `set`. After a refusal the directory agent tries no further domain controllers, so the account is not locked out. |

### Service does not start: access denied

If a virus scanner or EDR product has quarantined the directory agent, it looks like this:

- Under **Discovery › Agents** the directory agent no longer reports, often shortly after installation or after an update.
- `Start-Service SentryAssetsDirectory` fails, `sc.exe start SentryAssetsDirectory` reports `FAILED 5: Access is denied`.
- `Test-Path "$env:ProgramFiles\SentryAssets\Directory\sentryassets-directory.exe"` returns `False`, or the file cannot be opened.
- The Windows event log often shows nothing, because the EDR product intervenes itself and logs only in its own console.

How to fix it:

<Steps>

1. **Check the EDR product's console:** search the quarantine and the event or detection log for `sentryassets-directory` or the path of the program folder. It shows the time, the computer and the rule that triggered. For managed products this view is in the central console, not on the computer.

2. **Set up an exclusion** for the program folder as described under [Exclusions in virus scanners and EDR](#exclusions-in-virus-scanners-and-edr), and wait until the policy has reached the computer.

3. **Bring the program back:**
   - If `sentryassets-directory.exe.old` is still in the program folder after an update, rename it back to `sentryassets-directory.exe` and start the service with `Start-Service SentryAssetsDirectory`. The directory agent then updates again, this time with the exclusion in place.
   - Otherwise restore the file from quarantine and start the service.
   - If neither works, create a new rollout token under **Settings › Directory services** and run the installation command again (steps 2 and 3 under [Setting it up](#setting-it-up)). It downloads and checks the program anew. The access to AD in `C:\ProgramData\SentryAssets\Directory` is kept unless the scanner deleted it; otherwise set it up again with `set`. As the computer is then a new registration, choose it as the directory agent in the connection afterwards and block the old registration.

4. **Check the result:** `Get-Service SentryAssetsDirectory` shows `Running`, and **Test connection** under **Settings › Directory services** succeeds.

</Steps>
